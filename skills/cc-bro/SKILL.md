---
name: cc-bro
description: Delegate a ticket from this project to a named native Codex or pi worker, steer running work, isolate changes in Git worktrees, assign an independent review, and accept results.
---

Stay in the current project. Use the installed launcher {{launcher}} for every command below. Treat the ticket name, message and other values as separate quoted shell arguments.

1. Dispatch with {{launcher}} say research "the task" --bg --json. The default worker is project-specific. Choose --worker codex or --worker pi:<provider> to override it. pi:openai-codex uses the Codex subscription through pi. pi selects a model from the allowed provider, or you can pass --model provider/model-id. Reuse a name to continue its native context after a turn finishes; choose a different name for parallel work.
2. Immediately start a Bash tool call with run_in_background: true running {{launcher}} wait research 1 --json, using the exact name and turn from the receipt. The CLI persists the result before Bash completes and Claude Code delivers its task notification. A receipt alone does not mean the work succeeded.
3. After notification, read the output and check {{launcher}} show research --json. Inspect the result or ask for revisions; when accepted run {{launcher}} done research.
4. After interruption use {{launcher}} ls --json and reattach wait for the recorded turn. Use show --all for history, stop to cancel, and ui for the board. If no project is registered, tell the user to run cc-bro init at its root and choose allowed worker IDs and a project default.

5. Choose --worktree on the first say for parallel code changes or whenever the manager needs an isolated diff: {{launcher}} say auth-fix "Fix the failing auth test" --worktree --bg --json. It starts from committed HEAD, not the manager’s uncommitted files. Omit it for research or work that needs the current checkout. The manager chooses; cc-bro never adds it automatically. Reuse the name to keep its checkout.
6. To clarify work already running, use {{launcher}} say auth-fix "Also cover an expired token" --bg --json. outcome=injected means the worker confirmed delivery to the current turn. outcome=queued means wait for the returned next turn; multiple queued messages go in order into that turn. outcome=rejected means read the reason; if delivery was uncertain inspect show --all before retrying. Do not guess a turn or launch another writer to deliver the same instruction.
7. After the writer finishes, use {{launcher}} review auth-fix --by pi:deepseek --bg --json when you want an independent check before accepting code, especially for risky changes. Choose a different allowed worker ID. A pi-written ticket can go to --by codex, and codex and pi:openai-codex can review each other. To have Claude do the review, use your own native Claude Code subagent within the manager chat. The reviewer receives the turn’s instructions, final reply and Git change summary in the writer’s checkout. Start the background wait using the review receipt’s own name and turn. Leave the checkout unchanged during review. Send requested fixes to the original writer, then create a new review for that turn if needed.
8. Accept the reviewer and writer separately. On the writer, done prints a cleanup reminder. Inspect its branch, uncommitted and untracked files; the manager decides what to preserve or integrate. Neither a review nor done merges or deletes anything.
