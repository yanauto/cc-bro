# 常见问题

从你遇到的提示或工单现象入手，找到对应的检查方法。

## 工人已经登录，为什么还是提示不允许？

登录和项目授权是两件事。在项目根目录运行 `cc-bro init` 查看已有策略，需要时显式更新允许名单。`codex`、`pi:openai-codex` 和 `pi:deepseek` 是三个不同的标识。参见[项目允许名单](allowlist.md)。

## 为什么不能给同一个名字换模型？

一个名字绑定一段原生会话。切换工人或模型时，请另起名字。pi 可以用 `pi --list-models` 查看列表，填写已放行厂商提供的完整 `provider/model-id`。

## 关了经理对话，工单会停吗？

关闭对话不会停止本机服务。用 `cc-bro ls` 找单，`cc-bro show NAME --json` 看状态，再用 `cc-bro wait NAME TURN` 等待未完成的轮次。只想取消这一个工人时，用 `cc-bro stop NAME`。

## 为什么审查者看不到我刚才的改动？

worktree 从已提交的 HEAD 开始。请在看板上核对写单的分支和文件，等正确轮次结束，包括排到下一轮的插话。审查过程中保持写单目录不变。参见[独立 worktree 与审查](review-worktree.md)。

## 我该去哪填密钥、打开旧经理室？

在所选工人的 CLI 中登录，在实际项目里打开 Claude Code。看板配置页可以打开 CLI 登录命令，不收集密钥。如遇不兼容的旧服务，按[从 0.1.0 升级](upgrade.md)处理。

## 列表里的模型运行失败

CLI 目录不保证账户额度和权限。查看错误原因，明确选择另一个已允许的模型；cc-bro 不购买额度，也不悄悄换厂商。

## 自定义工人没有缓存或工具步骤

这是文档说明的降级能力。续会话经过试跑验证，Git 改动摘要、审查、worktree 仍可使用。
