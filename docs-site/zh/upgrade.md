# 升级

## 从 0.3.0 升级

安装 `cc-bro@0.3.1`，再运行 `cc-bro shutdown`、`cc-bro setup` 更新服务和用户技能。想让在跑的单做完就先等完成：停机会停止该服务所有项目的运行单和排队单。保留原有设置、具名会话和工单历史；自动发现不扩大权限。

`roster` 与 `roster --json` 改为默认紧凑输出。脚本需要具体变体、token 上限或完整目录条目时，使用 `roster --json --full`，也可加 `--worker ID` 只查一个 bro。两种模式的未允许 bro 都只有 `id` 和 `allowed:false`，隐藏模型都不出现。每个 bro 可设全局与项目默认值，不会把隐藏或旧默认模型偷偷换成其他型号。

## 从 0.2.0 升级

安装 0.3.1，先等想保留的任务完成，再运行 `cc-bro shutdown`、`cc-bro setup`。新版保留 0.2 登记库、工单、会话和逐项目允许名单，不会自动放行新增 CLI。先检查 `cc-bro roster`，再在配置页增加工人。遇到服务协议不匹配时会给出可直接执行的停机命令。

## 从 0.1.0 升级

0.2.0 移除了经理室。经理就是你在实际项目里打开的 Claude Code 对话。新版另用登记库，不会导入 0.1.0 工单、经理笔记或项目权限。

## 1. 决定何时停旧服务

如果想让正在运行和排队的单做完，就先等它们完成。有用的旧经理室和笔记可以留下，升级不需要删除这些目录。

## 2. 安装新版，停止旧服务

```sh
npm install -g cc-bro@0.3.1
cc-bro shutdown
cc-bro setup
```

即使 `init` 或 `ls` 提示协议不兼容，也可以用**新版** CLI 停掉 0.1.0 服务。停机会停止该服务下所有项目的运行单和排队单；未完成的轮次不会自动续跑。已经写入的文件和 0.1.0 工单库仍在磁盘上。

## 3. 重新登记实际项目

离开旧经理室，在希望工人使用的代码仓库根目录打开终端，执行：

```sh
cc-bro init
cc-bro ls
```

按提示选择允许的工人和默认工人。从 0.1.0 重新登记后，看到空工单列表是正常的。在**这个项目目录**打开 Claude Code，输入 `/cc-bro`。可以按[第一张工单](quickstart.md)走一遍验证。
