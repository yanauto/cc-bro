# 工人配置页

运行 `cc-bro ui`，点击页头的**配置**。选择**全局默认**或已登记项目。页面展示检测结果和 cc-bro 生效配置，不编辑其他 CLI 的配置文件。

## 检测与登录

**刷新检测**检查命令是否安装、版本和能力。Codex 用 app-server 的 `model/list`、`config/read`、`account/read`；pi 用不派活的 RPC 状态／模型查询和 `auth check --no-refresh`；agy 用 `models` 和只读 `/model`、`/effort`；Cursor 用模型列表、`status` 以及公开模型配置。只保留所需的非敏感字段；必要时仅检查凭据文件是否存在，不打开读取值，也不读取会话历史。

登录状态未知不等于未登录。点击**打开 CLI 登录**，由它在终端执行自己的登录命令。pi 在交互界面用 `/login` 选择厂商。认证、刷新和存储都归 CLI；完成后刷新检测。

**在终端安装**和**在终端升级**会打开官方安装器或更新命令，是用户明确触发的操作，会改变该 CLI 安装。检测本身不会安装、升级或写 CLI 配置。

## 全局与项目

- 全局备注、模型和档位默认值、规矩可继承，项目可单独覆盖。
- 已有项目允许名单保持独立。勾选**继承全局允许名单和默认 bro**才会跟随全局，否则在本项目单独选允许的 ID 和默认值。
- 项目规矩默认追加到全局规矩；勾选**本项目规矩覆盖全局规矩**可替换全局集合。
- bro 的项目字段覆盖相应全局字段；**移除本项目覆盖**恢复该 bro 的全局继承。
- **保存配置**写入 cc-bro 登记库，下次派活生效。另一页已经改过配置时会要求刷新，避免悄悄覆盖。

在工人列表输入 `pi:厂商` 可添加 pi 厂商，再明确放行；不会连带允许其他厂商。其他 CLI 用 `custom:名称`，见[自定义 CLI](custom-cli.md)。

经理提议的备注在用户确认前一直待处理。确认前会展示原备注；忽略提议保留原内容。
